# AgentDeck

**Одно рабочее пространство на Mac для всех ИИ-агентов для программирования, которыми вы уже пользуетесь.**

Запускайте Claude Code, Codex, Gemini CLI, Kimi Code и собственные модели бок о бок. Читайте результаты их работы в чистом, структурированном виде, проверяйте каждый diff, отвечайте на их вопросы и запросы подтверждения в одном месте и позвольте им планировать, реализовывать и проверять работу друг друга.

Ваши CLI. Ваши аккаунты. Ключи API не нужны.

## Зачем нужен AgentDeck

Агенты для программирования отлично работают в терминале — пока вы не запустите трёх из них в пяти проектах. Запросы подтверждения уезжают вверх, diff теряются в логах, а чтобы один агент проверил работу другого, приходится копировать и вставлять.

AgentDeck оставляет агентов в точности такими, какие они есть, и даёт им полноценное рабочее пространство:

- **Он запускает настоящие CLI.** `claude`, `codex`, `gemini` стартуют из вашей собственной установки, с тем же PATH, конфигурацией и входом, что и в Терминале. Если что-то работает в вашем терминале, оно работает и здесь.
- **Он никогда не трогает ваши учётные данные.** Каждый агент входит через собственную процедуру входа. AgentDeck не читает, не хранит и не передаёт токены; ключи API, которые вы добавляете для собственных моделей, остаются в связке ключей macOS.
- **Всё остаётся на вашем Mac.** Сессии хранятся в локальной базе данных SQLite. Никакого аккаунта, никакой телеметрии, никакого сервера.

## Что можно делать

### Работайте с любым агентом в любом проекте

Каждый проект — это папка; каждая сессия — это один агент, работающий в ней. Меняйте агента до первого сообщения, выбирайте из всех моделей, которые предлагает каждый агент, и переключайте модель прямо посреди разговора. Начните чат без проекта, переносите сессии между проектами, переименовывайте их или импортируйте сессии, которые Claude Code, Codex и Gemini CLI уже сохранили на вашем Mac; разговор продолжится с того же места.

Можно выбрать и то, насколько усердно агент думает. У Claude Code и Codex рядом с моделью есть настройка **усилия** (от низкого до максимального, только уровни, которые поддерживает эта модель). Меню показывает усилие, с которым агент работает прямо сейчас; изменение применяется сразу, пока Claude Code работает, а в Настройках задаётся усилие, с которым начинаются новые сессии.

### Проверяйте изменения так же, как ревьюите pull request

Каждый файл, который затрагивает агент, появляется с diff рядом или в едином виде, файл за файлом, с навигацией с клавиатуры и отметками «просмотрено». Ничего не коммитится и не пушится за вас.

Скриншоты и изображения, которые агент делает или просматривает (скриншот симулятора, отрисованная страница, изображение, которое он читает), появляются прямо в разговоре и на вкладке «Предпросмотр»; нажмите на любое, чтобы открыть его в полном размере.

![Ревью изменений агента в режиме «рядом»](../screenshots/readme/review.png)

### Подтвердите, отклоните или позвольте спросить

Команды и правки, которым нужно ваше согласие, появляются в виде карточек: что будет запущено, где, на что это повлияет и насколько это рискованно. Режим планирования позволяет агенту сначала изучить код и предложить план, прежде чем что-либо менять. Когда у агента есть вопрос (AskUserQuestion у Claude Code, request_user_input у Codex), вы получаете настоящую форму: выберите один вариант, несколько или напишите свой.

![Агент задаёт два вопроса: один с одиночным выбором, другой с множественным](../screenshots/readme/question.png)

### Пусть агенты работают вместе

- **Рабочие процессы: план → реализация → ревью.** Назначьте любого агента на каждый этап, например Claude Code планирует, Codex реализует, Claude Code проводит ревью. Каждый этап передаёт работу дальше, как только закончит, замечания ревью сразу возвращаются исполнителю, а процесс останавливается, когда ревьюер пишет APPROVED. Обычные запросы подтверждаются за агентов автоматически; рискованные (удаление, push, деплой, учётные данные, всё, что за пределами проекта) по-прежнему ждут вас.
- **Передать.** Отправьте любой план или ответ другому агенту в один клик.
- **Эстафета.** Два агента общаются друг с другом, пока один из них не скажет DONE.

![Рабочий процесс «план, реализация, ревью»: Codex реализовал, Claude Code провёл ревью и подтвердил](../screenshots/readme/workflow.png)

### Боты, которые продолжают работать

Бот — это агент, который остаётся. Дайте ему имя, работу, инструкции, агента и модель (Claude Code, Codex, Gemini CLI, Grok Build, Kimi Code, Antigravity или ваши собственные модели), а затем поручайте ему задачи. Он выполняет их в фоне, пока вы заняты чем-то другим.

- **Своё место.** У каждого бота есть своя папка (`~/AgentDeck/Bots/<name>`), и он работает в ней, если в задаче не указан проект. Любую задачу можно направить в любой проект: бот ведёт отдельный разговор для каждого места, поэтому помнит, что и где он делал.
- **Очередь задач.** Добавляйте задачи, пока бот занят: он выполняет их по одной. Ставьте на паузу, продолжайте, отменяйте или повторяйте, а у каждой завершённой задачи результатом остаётся отчёт бота.
- **Память.** У каждого бота в его папке есть короткий файл памяти. Бот читает его в начале каждой задачи и записывает то, что стоит запомнить: соглашения, решения, где что лежит, что вы предпочитаете. Прочитать и отредактировать его можно на странице бота.
- **Расписания.** «По будням в 9:00: проверить pull request'ы, смерженные вчера», «каждые 6 часов: искать нестабильные тесты». Каждый запуск встаёт в очередь, как любая задача.
- **Бот-менеджер.** Боты могут передавать части задачи другим ботам и ждать их результатов с помощью собственных инструментов AgentDeck (`list_bots`, `delegate_task`, `wait_for_tasks`). Ведущий бот может разделить работу между ревьюером, тестировщиком и автором текстов, а потом свести их отчёты воедино.
- **Без присмотра, но не без контроля.** Пока бот работает над задачей, обычные запросы внутри его папки и проекта задачи подтверждаются за него автоматически. Всё рискованное (удаление, push, деплой, учётные данные, всё за этими пределами) и каждый вопрос ждут вас, а на боковой панели у бота появляется «Ждёт вас».
- **Telegram.** Подключите собственного Telegram-бота (токен от @BotFather хранится в вашей связке ключей) и привяжите свой чат с помощью кода. После этого задачу можно написать с телефона, и ответ бота придёт туда же; чтобы выбрать бота, начните сообщение с его имени («Reviewer: …»). Когда бот ждёт вас, рискованный шаг, вопрос или план приходит с кнопками: разрешить, отклонить, выбрать ответ. AgentDeck сам запрашивает сообщения у Telegram, поэтому на вашем Mac ничего не открыто для интернета, а отвечает он только тем чатам, которые вы привязали.

- **Подключения.** Боты могут не только писать код. В разделе Настройки → Подключения добавьте браузер (Playwright), GitHub, Notion, Календарь, Напоминания, Почту и Заметки на вашем Mac (через сами приложения и учётные записи, которые в них уже есть) или любой MCP-сервер по команде или адресу, каждое со своей учётной записью; токены остаются в вашей связке ключей. Затем выберите для каждого бота, чем он может пользоваться. Пока бот работает над задачей, всё, что подключение читает, разрешено; всё, что оно меняет (слияние pull request, добавление события, открытие черновика письма), ждёт вас, если только вы не разрешили этому подключению действовать самостоятельно. Письма бот не отправляет никогда.
- **Триггеры.** Помимо расписаний и Telegram, бот получает работу, когда меняется веб-страница (цена, объявление), в папке появляются новые файлы, issue или pull request в вашем репозитории получает метку `agentdeck` или скрипт на вашем Mac вызывает его хук (`curl -X POST http://127.0.0.1:47810/hooks/…`). Кроме того, боты могут сразу сообщить вам что-то через `notify_me`: в Telegram и уведомлением.
- **Готовые боты.** Начните с исследователя, помощника по входящим, планировщика дня, автора для соцсетей, наблюдателя или разработчика и измените то, что нужно.

![Бот разбирает свою очередь, а его расписания и память — на соседней вкладке](../screenshots/readme/bots.png)

### Изолируйте работу в git worktree

Запустите сессию в отдельном worktree и ветке, чтобы агент не мог испортить вашу рабочую копию. Смотрите граф веток в разделе Git, а затем слейте worktree обратно (с понятным предупреждением, если обе стороны изменили одни и те же строки) или удалите его.

### И не только

- **Настройка агентов.** Редактируйте `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, навыки, команды и субагентов — глобальные и для отдельных проектов — в одном дереве.
- **Умный терминал.** Ваша собственная оболочка в папке проекта. Спросите любого агента о выделенном фрагменте или последних 80 строках, а кнопка «Объясни эту ошибку» сделает это в один клик.
- **Прикрепляйте что угодно.** Перетаскивайте файлы или папки, вставляйте скриншоты или выбирайте файлы. Изображения доходят до агента именно как изображения.
- **Ваши модели.** DeepSeek, Kimi, GLM (Z.ai), Ollama, LM Studio, OpenRouter или любой эндпоинт, совместимый с OpenAI или Anthropic, — с теми же подтверждениями, режимом планирования и рабочими процессами.
- **Лимиты тарифа на виду.** Под полем сообщения в сессиях Claude Code и Codex видно, какую часть 5-часового и недельного лимитов вы уже израсходовали и когда они сбросятся.
- **Вход там, где он нужен.** Когда агенту нужно войти в аккаунт, кнопка запускает его собственную процедуру входа во встроенном терминале и отправляет ваше сообщение снова.
- **Обновляется сам.** Новые версии подписаны и нотаризованы, а каждое обновление перед установкой проверяется ключом, встроенным в приложение.

## Бережно к ресурсам Mac

AgentDeck — нативное приложение на Tauri: небольшое ядро на Rust и собственный WebKit macOS, без встроенного браузерного движка.

| | Измерено на Mac (релизная сборка, Мониторинг системы) |
|---|---|
| Загрузка | Образ диска 22 МБ (Apple Silicon + Intel в одном приложении) |
| После установки | 50 МБ |
| Память самого AgentDeck | ~31 МБ приложение + ~207 МБ интерфейс + ~18 МБ системные вспомогательные процессы ≈ **256 МБ** |
| CPU в простое | **0,1 %**, без пробуждений в простое |
| Запуск | Интерфейс загружает основной бандл 446 КБ; ревью, терминал, галерея и настройки загружаются при открытии |

Агенты работают как отдельные процессы и используют собственную память — примерно 140–210 МБ каждый во время работы (измерено на Linux: Claude Code ~188 МБ, Codex ~159 МБ). Чтобы держать это под контролем, агент, простаивающий 10 минут, закрывается (его разговор продолжится, когда вы напишете снова), одновременно открыто не более 6 агентов, а длинная история загружается по 80 ходов за раз.

## Поддерживаемые агенты

| Агент | Как AgentDeck с ним общается | Вход |
|---|---|---|
| **Claude Code** | `claude` со stream-json и его инструментом запроса разрешений | Claude Pro, Max, Team или Enterprise либо Anthropic Console |
| **Codex** | `codex app-server`, JSON-RPC через stdio | Подписка ChatGPT или ключ API OpenAI |
| **Gemini CLI** | Agent Client Protocol | Аккаунт Google Workspace или Cloud либо ключ API Gemini |
| **Grok Build** | Agent Client Protocol | Аккаунт xAI или ключ API |
| **Kimi Code** | `kimi acp`, Agent Client Protocol | Подписка Kimi Code или ключ API Moonshot AI |
| **Antigravity** *(экспериментально, по умолчанию выключен)* | `agy` в headless-режиме со stream-json | Аккаунт Google; см. примечание в Настройках об условиях Google |
| **Ваши модели** | Встроенный агент AgentDeck или Claude Code для API, совместимых с Anthropic | Ключ API в вашей связке ключей |

Установите хотя бы одного. Экран первого запуска показывает, какие агенты уже есть на вашем Mac, и устанавливает остальные или выполняет вход в них официальной командой каждого агента — в Терминале, где видно, что она делает.

## Установка

1. Скачайте последний `AgentDeck-<version>.dmg` со страницы [Releases](https://github.com/kalismeras61/agentdeck/releases/latest).
2. Перетащите AgentDeck в «Программы» и откройте его. Приложение подписано и нотаризовано, поэтому открывается двойным щелчком.
3. Пройдите шаги **Начать**, чтобы настроить агента, а затем откройте папку проекта.

macOS 12 или новее, Apple Silicon или Intel.

## Как это работает

```
┌──────────────────────── AgentDeck (Tauri app) ────────────────────────┐
│  React UI: conversation, diffs, approvals, questions, workflows       │
│                │  validated, provider-neutral events (Zod)            │
│  Rust core: sessions · SQLite · git · PTY · workflow engine           │
└──────┬──────────────┬──────────────┬──────────────┬───────────────────┘
       │ stream-json  │ JSON-RPC     │ ACP          │ OpenAI / Anthropic API
       ▼              ▼              ▼              ▼
   claude          codex app-server  gemini, grok,  your models
                                     kimi
   (your install, your sign-in, your folder)
```

- Каждый агент работает как дочерний процесс в папке сессии, с окружением вашей login-оболочки.
- Их вывод сохраняется как есть, затем нормализуется в единый поток событий (сообщения, вызовы инструментов, diff, запросы подтверждения, вопросы, планы) и проверяется, прежде чем что-либо будет отображено. Всё некорректное показывается как понятная ошибка и никогда не выполняется.
- На запросы подтверждения отвечаете только вы — или рабочий процесс, если запрос обычный; ничего опасного не подтверждается автоматически.
- У фронтенда нет доступа к оболочке: он может вызывать только собственные узкие команды AgentDeck.

## Сборка из исходников

Требования: Node 22+, Rust 1.77+ и инструменты командной строки Xcode.

```bash
npm install

npm run dev                 # web preview with labeled demo data, http://localhost:1420
npm run tauri dev           # desktop app

# Checks
npm run typecheck && npm run lint && npm test
(cd src-tauri && cargo fmt --check && cargo clippy && cargo test)

# End to end with the real CLIs against local stand-in APIs (no accounts needed)
python3 scripts/mock_anthropic.py 8787 & python3 scripts/mock_openai.py 8788 & python3 scripts/mock_gemini.py 8789 &
(cd src-tauri && AGENTDECK_IT=1 cargo test -- --ignored --test-threads=1)

npm run tauri build         # .app / .dmg
```

Процесс выпуска релизов (подписанных, нотаризованных, универсальных, с автообновлением) описан в [docs/RELEASING.md](../RELEASING.md); что уже реализовано и как проверяется каждая часть — в [docs/STATUS.md](../STATUS.md); протоколы агентов — в [docs/PROVIDERS.md](../PROVIDERS.md).

## Участие в разработке

Issues и pull request приветствуются. Перед открытием PR запустите проверки, описанные выше, и пишите текст интерфейса коротко и просто.

**Переводы.** Переводы интерфейса сделаны с помощью ИИ и проверены тестами, но пока не носителями языка, поэтому исправления очень приветствуются: отредактируйте `src/locales/<language>.json` и запустите `node scripts/i18n-validate.mjs`. Новый текст интерфейса проходит через `t()`; см. [docs/I18N.md](../I18N.md).

AgentDeck распространяется под лицензией AGPL и, отдельно, под коммерческой лицензией. Чтобы это оставалось возможным, участников просят подписать лицензионное соглашение участника (CLA) при первом pull request.
